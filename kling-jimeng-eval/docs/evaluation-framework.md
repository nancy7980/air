# 可灵 vs 即梦 视频生成能力评测框架

> 作者视角：可灵视频模型产品经理候选人 · 作品集
> 目标：建立一套**可复现、可量化、可解释**的视频生成模型横向评测体系，并用 ComfyUI 工作流自动化执行。

> **落地说明（云端原生）**：工作流在 ComfyUI Cloud 上用官方节点实现——可灵走官方 Kling 节点，
> 即梦走官方 **ByteDance Seedance** 节点（即梦视频的同源模型），LLM 评委用官方 **Gemini** 多模态节点。
> 全程无需自定义节点。

---

## 1. 为什么要做这套评测（产品视角）

视频生成模型的「好坏」是高度主观的，但产品决策不能靠拍脑袋。作为 PM，我需要回答三类问题：

1. **竞品在哪些场景比我们强 / 弱？** —— 指导模型迭代优先级
2. **同样一句 prompt，用户体感差异有多大？** —— 指导 prompt 引导与产品文案
3. **质量、成本、效率三角如何权衡？** —— 指导定价与算力策略

因此评测不止是「打个分」，而是一套**决策支持系统**：受控输入 → 多维评分 → 可视化结论 → 迭代建议。

---

## 2. 评测设计原则

| 原则 | 落地做法 |
|------|----------|
| **受控变量** | 同一 Prompt / 输入图 / 运动描述 / 时长 / 分辨率，两家保持一致，只比模型本身 |
| **盲评去偏** | 评分时以「视频A / 视频B」呈现，评委不知道哪个是可灵（降低品牌先验） |
| **多维拆解** | 把「好不好」拆成 5 个可独立打分的维度，避免笼统 |
| **主客观结合** | LLM 主观打分（体感）+ 客观指标（耗时/成本/成功率）交叉验证 |
| **可复现** | 固定 seed、固定 rubric、temperature=0，结果可重跑 |
| **场景覆盖** | 标准测试集覆盖运动/物理/多主体/镜头/风格等典型挑战（见 test-prompt-set.md） |

---

## 3. 评分维度与权重（核心 Rubric）

每个维度按 **1–10 分**，加权得到总分。权重体现「对用户体验的影响度」。

| # | 维度 | 权重 | 评什么 | 典型扣分项 |
|---|------|------|--------|-----------|
| 1 | **画面质量** Visual Quality | 25% | 清晰度、细节密度、无压缩/噪点伪影 | 糊、块状伪影、过曝 |
| 2 | **运动合理性** Motion Quality | 25% | 运动自然、符合物理、无闪烁/形变 | 肢体扭曲、鬼影、运动僵硬 |
| 3 | **文本一致性** Prompt Adherence | 25% | 是否准确还原主体/动作/场景/数量 | 漏主体、动作错误、数量错 |
| 4 | **时序一致性** Temporal Consistency | 15% | 主体/背景跨帧稳定、不漂移突变 | 主体变形、背景闪变 |
| 5 | **美学表现** Aesthetics | 10% | 构图、光影、色彩、电影感 | 构图平淡、色彩脏 |

**加权总分** = Σ(维度分 × 权重)，满分 10。

> 权重设计理由：前三项（画质/运动/一致性）直接决定「能不能用」，各占 25%；时序一致性是视频区别于图像的关键，给 15%；美学是加分项，给 10%。权重可按业务场景调整（如广告片提高美学权重）。

## 4. 评分方式：LLM-as-Judge + 轻量客观指标

### 4.1 主观打分（自动）
- 工作流抽取每个视频的 8 帧关键帧 → 连同 Prompt + Rubric 喂给多模态大模型评委
- 评委按上表逐维打分、给理由，输出结构化 JSON
- `temperature=0` 保证可复现；A/B 盲标降低品牌偏见

**评委输出示例（JSON）**
```json
{
  "results": [
    {"dimension": "Visual Quality",      "kling_score": 8, "jimeng_score": 7, "reason": "可灵毛发细节更锐利，即梦轻微涂抹感"},
    {"dimension": "Motion Quality",      "kling_score": 9, "jimeng_score": 6, "reason": "即梦奔跑步态出现一次轻微滑步"},
    {"dimension": "Prompt Adherence",    "kling_score": 8, "jimeng_score": 8, "reason": "两者均还原雪林+逆光+追拍"},
    {"dimension": "Temporal Consistency","kling_score": 8, "jimeng_score": 7, "reason": "即梦背景树木有一次闪变"},
    {"dimension": "Aesthetics",          "kling_score": 8, "jimeng_score": 8, "reason": "光影氛围相当"}
  ],
  "weighted_total": {"kling": 8.25, "jimeng": 6.95},
  "winner": "kling",
  "summary": "可灵在运动稳定性与画面锐度上领先，即梦在美学氛围上接近。"
}
```

### 4.2 客观指标（人工/脚本补录，交叉验证）
LLM 打分是「体感」，仍需硬指标兜底。这些指标不需要复杂模型，却最贴近产品决策：

| 指标 | 含义 | 为什么 PM 关心 |
|------|------|----------------|
| 生成耗时 | 提交→出片秒数 | 直接影响用户等待体验与并发成本 |
| 一次成功率 | 不重试即可用的比例 | 影响「有效成本」与口碑 |
| 单条成本 | 一次生成的 API 计费 | 定价与毛利的基础 |
| 实际分辨率/时长 | 是否达到标称值 | 宣传一致性 |
| 失败/驳回率 | 内容审核拒绝、报错 | 影响可用性 |

## 5. 测试集设计

为避免「挑好的样本」带来的偏差，使用**固定的标准化测试集**，每条 prompt 针对一种已知的视频生成难点。详见 [`test-prompt-set.md`](./test-prompt-set.md)，覆盖 10 类挑战：

简单运动 / 复杂物理 / 多主体交互 / 镜头语言 / 精细纹理 / 文字渲染 / 风格化 / 人物表情 / 流体 / 长时一致性。

I2V 另配 5 张标准输入图（人物/风景/产品/动物/插画），评运镜与首帧保真。

## 6. 评测流程（端到端）

```
┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ ① 标准测试集 │ → │ ② 并排生成    │ → │ ③ 抽帧+LLM评委 │ → │ ④ 看板+结论   │
│ Prompt/图    │   │ 可灵 / 即梦   │   │ 5维打分+理由  │   │ 雷达图+建议   │
└──────────────┘   └──────────────┘   └──────────────┘   └──────────────┘
        ▲                                                          │
        └────────────────── 迭代建议反哺测试集 ────────────────────┘
```

1. 从测试集取一条输入，填入工作流左侧共享输入节点
2. Queue，两家在相同参数下各生成 T2V + I2V
3. 工作流自动抽帧、调用 LLM 评委、输出 JSON 评分卡
4. 把视频与评分填入 `comparison-dashboard.html` 看板
5. 汇总多条样本 → 形成维度均分、胜率、强弱场景结论

---

## 7. 结论如何呈现（交付物）

- **单样本**：评分卡 JSON + 雷达图（5 维对比）
- **汇总**：胜率表（按维度/按场景）、平均加权分、质量-成本散点
- **洞察**：「可灵在 X 场景领先 / 即梦在 Y 场景领先」+ 给本方产品的 3 条迭代建议

> 这一步是 PM 的价值所在：把数据翻译成**产品决策语言**，而不是停在分数。

---

## 8. 局限与诚实声明

- LLM 评委是「资深观点」而非绝对真理，需用客观指标交叉验证，必要时引入人工复核（小样本对齐 LLM 与人工评分的一致性）。
- 仅抽 8 帧评判，可能漏掉局部瞬时瑕疵；高精场景可加大抽帧数。
- 两家 API 的默认后处理（锐化/调色）不同，属于「产品整体体验」的一部分，评测时如实记录、不强行抹平。
- 测试集需持续扩充以防过拟合到特定题材。
