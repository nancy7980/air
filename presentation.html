AI 工具产品生态

技术如何重写产品形态——演进过程与竞品格局。

01
生态评测业务未来
演进过程 · 三个阶段

每一次技术跃迁，都重写了一次产品形态

模板填充时代 · 前 LLM
关键词匹配 + 素材库
本质是模板生意，AI 只是话术包装。
LLM 生成时代 · 2023
大纲生成 → 套模板渲染
解决了"内容从哪来"，没解决"排版好不好看"。
Agent 时代 · 2024 至今
规划 · 工具调用 · 代码排版 · 自检
从"填空题"变成"委托制作"。
第三阶段是三个技术变量的叠加：推理模型解锁规划、多模态解锁自检、代码能力溢出到设计领域——绕过了模板。
02
生态评测业务未来
竞品生态 · 四股势力

同一条赛道上，四种打法

传统办公厂商 AI 化

WPS AI · Copilot · Canva

资产：存量用户与格式心智

软肋：AI 是补丁非原生

AI 原生垂直工具

Gamma · AiPPT

资产：场景打磨深

软肋：模型靠采购，易被降维

千问在此

大模型厂商通用助手

Qwen · Kimi · 豆包

资产：模型红利 + 流量入口

软肋：场景纵深不足

通用 Agent 平台

Manus · GenSpark

资产：链路最完整

软肋：成本高、稳定性差

千问在第三股势力中，但多了两张牌——开源生态与阿里云 B 端通道（详见第三部分）。
02

竞品评测报告

一次 Agent 链路的拆解实验——链路评测 + 结果评测。

03
生态评测业务未来
评测设计

不测"哪家好看"，测哪家的 Agent 真的在思考

对象

Qwen / 豆包 / Kimi 等主流 AI PPT Agent。

任务

同一指令，含明确硬约束与抽象风格要求。

方法

链路评测（看思考过程）+ 结果评测（看交付质量）。

下面先用三个维度拆"链路"，再回到"架构差异"，最后落到"生成结果"的逐层质检。
04
生态评测·链路业务未来
链路维度一 · 抽象意图的转译能力

高级能力不是"听懂颜色"，
而是把抽象风格词转成可执行的视觉系统

用户输入

"落日飞车风格"

一个抽象到无法直接执行的风格词。

Agent 拆解
夕阳 公路 复古相纸 暖棕 深紫 橘黄 松弛 迷幻 浪漫
这考察的是 Agent 的规划深度——动手前想了几层。
05
生态评测·链路业务未来
链路维度二 · 硬约束的遵守能力

软能力的缺陷用户会原谅，
硬约束的违反直接摧毁信任

用户要求

1–10 页

豆包实际交付

11 页

豆包 · 实际 11 页⤢ 放大
页数 / 比例 / 语言 / 品牌元素是合同条款，不是参考建议。违反它，用户的感受是"它根本没在听我说话"。
06
生态评测·链路业务未来
链路维度三 · 内容组织的目标对齐能力

优秀的 Agent 理解"任务背后的任务"

目标识别

它识别出 PPT 的真实用途是"帮用户提升面试认知"，而非"介绍一个概念"。

叙事路径
概念理解→能力拆解→面试表达→误区规避
苏格拉底式追问 · 落地为类比

智能管家（解释 Agent）· 建筑师 vs 砌砖工（解释内容规划）· 自动驾驶级别（解释能力边界）。

07
生态评测·架构业务未来
从行为反推架构差异

架构的差异，最终都会以用户可感知的方式暴露

固定 Workflow

大纲 → 配图 → 渲染，步骤写死

快、稳，但不会变通，违反约束也不自知。

ReAct 单 Agent

边想边做、回头检查

灵活，但慢、贵、偶尔不稳定。

规划-执行分离 · 多 Agent

内容规划 / 设计系统 / 质检分工

上限最高，工程复杂度也最高。

豆包页数超标，大概率说明链路里缺少"交付前对照原始需求"的质检环节。
08
生态评测·结果业务未来
生成结果评测 · 评测标准

模拟用户真实容忍度：先排除硬伤，再谈审美

硬伤项 · 一票否决
文字溢出 / 图文遮挡 / 信息错误
专业项
信息层级 / 每页一个重点 / 图表选型
惊喜项
风格统一性 / 设计细节

在"硬伤"之上，再用三层标准逐项打分：

  • RAG 事实层：事实准确性 · Refusal 质量 · 引用准确
  • 内容层：观点质量 · 论证密度
  • 设计层：视觉层级 · 信息密度 · 留白与可读性
下面用千问与豆包的实测页面，逐层 show 我遇到的具体 case。
09
生态评测·结果业务未来
RAG 事实层 · ① 事实准确性

用于专业场景，一个过时数字就足以崩塌信任

豆包 · P5⤢

问题：标题拼写错误 copiloto · logo 截断成 Qwe · 写"Qwen 支持 32K Token"——已过时且错误（主流为 128K~1M）。

千问 · P8⤢

千问写 128K 上下文与多模态 Qwen-VL，与现状一致——事实层更可信。

10
生态评测·结果业务未来
RAG 事实层 · ② Refusal 质量 & ③ 引用准确

会"划边界、不乱引"的 Agent，才敢被信任

千问 · P9⤢

千问主动声明能力边界：误区一/二/三 + "L2.5 级辅助智能"——有 Refusal / 不确定性表达。

豆包 · P7⤢

豆包通篇只夸不拒；引用 25,500 美元/年、70-95%、6 小时→20 分钟等数字均无来源，伪造引用风险更高。

两者都没有真正的页码/段落引用，但豆包的"无源数字"在专业评审场景里风险最大。
11
生态评测·结果业务未来
内容层 & 设计层 · 没有全能选手

内容千问赢，设计豆包赢

豆包 · P3⤢

内容层：豆包"飞行家 / 魔力 / 飞行"等比喻重复多，论证密度不足；千问观点讲解更清晰。

千问 · P8⤢

设计层：千问信息过载、字号排版不合理、可读性差；豆包视觉层级 / 留白更合理，并用 icon 填充空白增可读性。

未来判断

Content Remix——工具的消失。

14
生态评测业务未来
未来判断 · Content Remix

AI 工具的终局不是更多垂直工具，而是工具的消失——它会成为 AI 回答的"渲染层"。

现在

有需求 → 想起某个工具 → 打开它
（用户自己做"需求到工具"的匹配）

未来

AI 识别意图带展示/汇报/传播属性 → 自动选择最佳形态
PPT / 网页 / 播客 / 信息图

类比：浏览器渲染 HTML，未来的 AI 助手渲染"意图"。佐证：NotebookLM 的音频概览——用户没要播客，产品主动 remix，成了爆点。
回到立论

让通义回答完问题后，
顺手把"最佳展示物"也给你

从工具到出口：不是更漂亮，而是可信、可交付、可复用；不是更多孤立工具，而是一个理解意图的渲染层。
