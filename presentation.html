02

竞品评测报告

一次 Agent 链路的拆解实验——链路评测 + 结果评测。

评测设计

评测重点：从思考过程而非外观入手

对象

Qwen / 豆包 / Kimi 等主流 AI PPT Agent。

任务

同一指令，含明确硬约束与抽象风格要求。

方法

链路评测（看思考过程）+ 结果评测（看交付质量）。

链路维度一 · 抽象意图的转译能力

维度一：抽象风格词的转译能力

用户输入

"落日飞车风格"

一个抽象到无法直接执行的风格词。

Agent 拆解为可执行视觉语言
夕阳公路复古相纸暖棕深紫橘黄松弛迷幻浪漫
这考察的是 Agent 的规划深度——动手前想了几层。高级能力不是"听懂颜色"，而是把抽象风格词转成可执行的视觉系统。
链路维度二 · 硬约束的遵守能力

维度二：对硬约束的遵守

用户要求

1–10 页

豆包实际交付

11 页

豆包 · 全 11 页
⤢ 点击放大
页数 / 比例 / 语言 / 品牌元素是合同条款，不是参考建议。软能力的缺陷用户会原谅，硬约束的违反会直接影响信任——"它根本没在听我说话"。
链路维度三 · 内容组织的目标对齐能力

维度三：内容组织的目标对齐

目标识别

识别出 PPT 的真实用途是"帮用户提升面试认知"，而非"介绍一个概念"。

叙事路径
概念理解→能力拆解→面试表达→误区规避
苏格拉底式追问 · 落地为类比

智能管家（解释 Agent）· 建筑师 vs 砌砖工（解释内容规划）· 自动驾驶级别（解释能力边界）。优秀的 Agent 理解"任务背后的任务"。

从行为反推架构

从行为差异反推架构差异

A

固定 Workflow

大纲 → 配图 → 渲染，步骤写死

快、稳，但不会变通，违反约束也不自知。

B

ReAct 单 Agent

边想边做、回头检查

灵活，但慢、贵、偶尔不稳定。

C

规划-执行分离 · 多 Agent

内容规划 / 设计系统 / 质检分工

上限最高，工程复杂度也最高。

豆包页数超标，大概率说明链路里缺少"交付前对照原始需求"的质检环节。架构差异，最终都会以用户可感知的方式暴露。
生成结果评测 · 评测标准

生成结果评测：先排硬伤，再看专业与设计

硬伤项 · 一票否决
文字溢出 / 图文遮挡 / 信息错误
专业项
信息层级 / 每页一个重点 / 图表选型
惊喜项
风格统一性 / 设计细节

在"硬伤"之上，再用三层标准逐项打分：

  • RAG 事实层：事实准确性 · Refusal 质量 · 引用准确
  • 内容层：观点质量 · 论证密度
  • 设计层：视觉层级 · 信息密度 · 留白与可读性

千问做 AI 工具的四点优势

二次开发反哺工具生态

04

阿里系场景纵深

钉钉 / 夸克 / 阿里云 / 电商

独立公司没有的入口

落地场景 · 按入口组织

把能力嵌进用户已有的工作流

入口场景关键优势
夸克学生答辩、求职作品集高频刚需，适合拉新
钉钉周报、述职、项目汇报文档上下文现成，"读完周报直接出汇报"
阿里云 API企业内训、销售方案批量定制B 端规模化
电商商家工具详情页、直播间素材批量、快、合规
每个入口都对应一类现成的上下文与流量——这正是"通用助手"补齐"场景纵深"的路径。
04

未来判断

Content Remix：工具弱化为输出层。

未来判断 · Content Remix

一个判断：AI 工具可能从"入口"
变成 AI 回答的"输出形态"

现在

有需求 → 想起某个工具 → 打开它
（用户自己做"需求到工具"的匹配）

未来

AI 识别意图带展示 / 汇报 / 传播属性 → 自动选择最佳形态
PPT / 网页 / 播客 / 信息图

类比：浏览器渲染 HTML，未来的 AI 助手渲染"意图"。佐证：NotebookLM 的音频概览——用户没要播客，产品主动 remix，成了爆点。
小结

从工具
到输出形态

不是更漂亮，而是更可信、可交付、可复用；不是更多孤立工具，而是一个理解意图的输出层。
